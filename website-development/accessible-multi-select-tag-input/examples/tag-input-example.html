Multi-Select Tag Input Accessibility

Accessibility Focus: This example demonstrates how to build a fully accessible multi-select tag input. Open your screen reader (VoiceOver on macOS, NVDA or Narrator on Windows) and press Tab to interact with the widgets using only your keyboard.

Flawed Tag Input Inaccessible

Built using simple styles. The closed tags cannot be focused by a keyboard user, close buttons have no accessible names or roles, and screen readers are completely silent during tag additions or deletions.

  • ❌ Zero Keyboard Navigation: You cannot highlight or select the active tags using arrow keys or the tab key.
  • ❌ Inaccessible Remove Button: The close button is just a raw symbol (×) with no programmatic label. Screen readers read it as "times" or "multiplication".
  • ❌ No Screen Reader Announcements: Pressing enter inserts the tag, but screen reader users have no confirmation.
Robust Tag Input Accessible

Implements roving keyboard focus. Keyboard users can hit Left Arrow when the input is empty to move visual focus into the list of tags, navigate with arrow keys, and delete them with Backspace or Delete. Screen readers get immediate status updates via ARIA live regions.

Type and press Enter to add. Use Left/Right Arrow keys to navigate and focus tags; press Backspace to delete.

  • ✅ Roving Focus: Focus remains single-entry on the page, but arrow keys let keyboard users navigate the tags effortlessly.
  • ✅ Safe Backspace Action: The first Backspace press on an empty input highlights the last tag; the second press confirms deletion, protecting users from accidental data loss.
  • ✅ Accessible close labels: Button has an explicit aria-label="Remove React", and is linked to its parent via aria-describedby.
  • ✅ Polite Live Announcements: Updates are instantly read aloud (e.g., "Added tag: JavaScript", "Removed tag: HTML. 2 tags remaining").
